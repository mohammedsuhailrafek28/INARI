# INARI demo UI (`/inari`) and Wispr Flow verification

## What was added (additive; no teammate-owned file rewritten)
- `client/src/pages/InariStudio.tsx` (new): one self-contained page using only `trpc.inari.*` and the existing tRPC client.
- `client/src/App.tsx`: one lazy import and one route line (`/inari`). This is the only edit to an existing file; if your frontend branch changed `App.tsx`, re-add those two lines.
- `client/public/demo/synthetic_statement.csv`: the synthetic sample (copy of `data/demo/fixture_debit_credit.csv`).

Flows on the page: import CSV/PDF (preview, then explicit confirm) -> snapshot -> advisor (`inari.ask`, `previous` echoed from the last `context`) -> what-if (`inari.simulate`) -> monthly report (`listReportMonths`, `monthlyReport`) -> No-Cost EMI check (`inari.emiCheck`). Advisor `proposedActions` render as confirm cards; `missingFields` become inputs (`idempotencyKey` is generated by the page); nothing runs until Confirm.

## Same origin
`pnpm build` then `pnpm start` serves the built frontend and `/api/trpc` from one Express origin. The demo cookie `inari_demo_id` (HttpOnly, SameSite=Lax) works only on that single origin. Required env for the demo: `NODE_ENV=production`, `WEALTHVERSE_DEMO_MODE=true`, `WEALTHVERSE_ALLOW_DEMO_IN_PRODUCTION=true` (all in `render.yaml`), plus `JWT_SECRET` and `INARI_IDENTITY_SECRET`. Without demo mode every `inari.*` call returns 401 "Please login" and the legacy global handler redirects to /login.

Synthetic data only. Demo identity is not real authentication. Data lives in server memory.

## Manual Wispr Flow verification (not yet performed by Claude; do this on the demo machine)
1. Open `http://localhost:<port>/inari` (or the deployed URL) in a fresh browser window.
2. Click "Load synthetic sample", then "Confirm import of 494 transactions". The snapshot should show income ₹85,102.00, expenses ₹57,476.04, surplus ₹27,625.96, savings rate 32.46%.
3. Click inside the advisor box (it is a normal `<textarea>`, auto-focused).
4. Activate Wispr Flow's hotkey and dictate: "How much did I spend on dining last month?"
5. Before sending, check that the box contains exactly what you said, including any self-corrections. The page does not edit the text (only leading/trailing whitespace is trimmed).
6. Press Enter (or "Ask"). Expect "In September 2026 you spent ₹3,377 on dining & delivery. That is ₹1,130 less than August 2026 (₹4,506)." plus the line "Deterministic financial reasoning ... no language model used".
7. Dictate "I spent 350 rupees cash yesterday on lunch". Expect a preview and an "Add this entry" card; press Confirm only if you want it recorded.
8. Dictate "What if my income drops by ten thousand?" Expect surplus ₹27,625.96 -> ₹17,625.96 and your ledger unchanged.
Only claim Wispr Flow works after steps 3-6 succeed on the actual machine.

## Known limitations
- Tab title and landing page still say "WealthVerse" (teammate-owned `client/index.html` and legacy pages).
- Legacy WealthVerse pages (`/dashboard`, `/avatar`, ...) still call legacy routers and are not migrated; `/inari` is the INARI demo surface.
- "no wait, I mean this month" style corrections are sent verbatim; the advisor answers with the latest month in the data.
- `create_claim` cards with missing `transactionId` ask for a raw transaction id; there is no transaction picker yet.
